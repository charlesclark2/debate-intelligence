## Summary

`debate_core.domain` now exists: the V1 vocabulary as frozen, `extra="forbid"` Pydantic v2 models
that already carry the §7 cloud data model's fields, so V2 swaps storage rather than schemas.
Eight modules ship — `base.py` (the model bases, the `Ulid`/`UtcDatetime`/`Sha256Hex`/`HttpUrlStr`/
`NonEmptyText` scalars and the injectable ULID factory), `enums.py`, `article.py`, `search.py`,
`card.py`, `citation.py` and `schema_export.py` — plus seven committed JSON Schemas generated by
`scripts/export_schemas.py`. The domain's only runtime dependencies are `pydantic` and
`python-ulid`; it imports no I/O library, AWS SDK, HTTP client or web framework.

The invariants are where the value is. A `Card` cannot hold `evidence_text` without a
`snapshot_id` and the offsets the quotation was taken at; it cannot be `VERIFIED` without also
having `normalizer_version` and at least one span; spans must sit inside the evidence and may not
overlap within a style; and a `CitationField` whose only source is a heuristic can never be marked
verified. 160 domain tests pass (100% statement and branch coverage of `domain/`), including
hypothesis round-trip properties for every model and a schema-staleness test.

Three things for the PM to look at first, all under **Decisions and assumptions** below: the
deliberate split in enum value casing, the choice *not* to enforce that `evidence_text` equals its
snapshot slice (that check belongs to the E03 verifier, which needs a mismatching card to be
constructible), and the two enum members added beyond the spec's list (`AccessStatus.UNKNOWN`,
`SearchStatus`) that the entities could not be defined without.

## Decisions and assumptions

**Two enum members the spec does not list, because the entities cannot be defined without them.**
`AccessStatus.UNKNOWN` is the state of an article that has been discovered through search but never
fetched; `v1-e04-t03-access-status` enumerates the seven values its *classifier* returns, and
`UNKNOWN` is deliberately not one of them (documented on the member). `SearchStatus`
(`COMPLETE`/`PARTIAL`/`FAILED`) is needed for `Search.status`, which §7 lists; the three values come
straight from `v1-e08-t01-federated-search-service`. `CitationFieldSource` is likewise new here, but
its seven values are quoted verbatim from `v1-e06-t01-citation-service` ac1.

**Enum value casing deliberately follows the specs' own split.** State enums serialize as
`SCREAMING_SNAKE_CASE` (`PAYWALLED`, `UNVERIFIED`, `USER_SUPPLIED`, `PARTIAL`) and label enums as
`lower_snake_case` (`scholarly`, `think_tank`, `underline`, `internal_link`, `meta_tag`,
`json_ld`). That is not tidy, but it is exactly how every downstream spec writes these tokens, and
enum values are a persisted wire format — normalizing them now would mean a migration later, and
matching them now means no spec statement becomes wrong. `tests/domain/test_enums.py` pins every
value so a future rename has to be deliberate. If the PM would rather have one convention, this is
the cheapest moment to change it.

**`evidence_text` is *not* checked against its snapshot slice.** The obvious invariant
(`end_offset - start_offset == len(evidence_text)`) was considered and rejected:
`v1-e03-t04-verifier` ac2 requires that a card with a single changed, inserted or deleted character
verifies as `UNVERIFIED` with `TEXT_MISMATCH` and a reported offset. That test needs a tampered
card to be *constructible*. Enforcing equality in the model would turn the verifier's most important
finding into a constructor crash. The domain therefore enforces that a location exists and is
well-formed; whether the text matches it is the verifier's answer. `test_card.py::
test_a_tampered_card_is_still_constructible_so_the_verifier_can_report_it` records the reasoning.

**`CardSpan` offsets are relative to `evidence_text`, not to the snapshot.** The card's own
`evidence_start_offset`/`evidence_end_offset` locate the quotation in the snapshot; spans mark up
the quotation. That is what the DOCX renderer needs, and it keeps spans valid regardless of where
in the source the quotation came from. `CardSpan` also drops §7's `card_id`: spans are nested
inside their card, so a back-reference would be a second copy of the truth. The repositories
denormalize it if their physical layout needs it.

**§7's `Search.user_id` is spelled `owner_id`**, so that every entity uses one name for the owning
user (§7 already uses `owner_id` on `Card`).

**Entities declare `owner_id`/`organization_id` themselves rather than inheriting them.** A `Card`
always belongs to a student (`owner_id` required); an `Article` describes a public source and may
have no owner (`owner_id: Ulid | None`). Narrowing an inherited optional field to a required one is
an invariance error under pyright strict, and the split is more honest anyway.
`test_base.py::test_every_entity_carries_tenancy_and_audit_fields` asserts every exported entity has
both fields plus `created_at`/`updated_at`/`revision`, so the convention is still enforced.

**`Card.provenance_mode` and `Search.status` have no defaults.** Defaulting `provenance_mode` to
`PUBLISHER_RETRIEVED` would make the strongest provenance claim the platform can make the thing that
happens when a caller says nothing — exactly the mislabelling `v1-e04-t05-article-service` forbids.
Defaulting `SearchStatus` would let a partial search look complete.

**`SourceSnapshot` uses `raw_blob_key`/`normalized_blob_key`, not §7's `s3_key`.** The V1 store is
the local filesystem behind the `SnapshotStore` port, and `v1-e03-t02-hashing-provenance` ac1 calls
for "the blob keys for raw and normalized content" — two keys, storage-neutral.

**Canonical URLs are plain validated strings, not `pydantic.HttpUrl`.** They are compared, hashed
and used as dedupe keys, so they must survive a round-trip byte for byte rather than be rewritten by
a URL normalizer. Canonicalization stays an explicit retrieval-layer step (E04).

**Models are frozen, with `evolve()` as the mutation path.** `model_copy(update=...)` skips
validation, which would let a caller walk around any invariant above; `evolve()` revalidates.
`test_evolve_cannot_smuggle_a_card_into_the_verified_state` is the regression test for that.

**ULIDs come from `python-ulid` rather than a hand-rolled encoder**, and are carried as
pattern-constrained strings (`^[0-7][0-9ABCDEFGHJKMNPQRSTVWXYZ]{25}$`) so the published schemas stay
simple and JSON round-trips are trivial. `new_id()` reads a `ContextVar`, so `use_id_factory()`
makes ids deterministic per thread or asyncio task without any model knowing about it.

**Schemas are rendered in serialization mode** (`model_json_schema(mode="serialization")`), because
what is published is the shape a model *produces* — what a repository stores and an API returns.
`render_schemas()` lives in `debate_core.domain.schema_export` (pure, no filesystem access) so the
script and the staleness test share one list of exported models; the script does all the writing.

**Data minimization holds.** The only person-identifying fields in the whole layer are `owner_id`
and `organization_id`, both opaque ULIDs. `Citation.authors` and `author_credentials` name
*published* authors of sources, never students.

## Follow-up work

* **`Card` has no generated-artifact metadata field yet.** `v1-e06-t02-card-service` ac4 requires a
  persisted card to carry `GeneratedArtifactMetadata` (model id, prompt ids/versions, temperature).
  That model is E06's to define, and adding the field to `Card` belongs in that task — it is a
  schema change, so it should be a deliberate one. Belongs to `v1-e06-t02-card-service`.
* **V2's `PASTED` provenance will need the evidence rule relaxed.** This task's spec forbids "a Card
  model that can hold `evidence_text` without `snapshot_id` and span offsets", and the model enforces
  it. Every V1 mode is snapshot-backed, including `FILE_IMPORT` (`v1-e31-t03` snapshots the source
  document), so nothing in V1 is blocked. But `v2-e18-t01-card-parser` describes `PASTED` cards as
  explicitly not snapshot-backed. When that task lands, either it models pasted cards as their own
  type or this invariant becomes conditional on `provenance_mode` — a spec change either way.
  Belongs to `v2-e18-t01-card-parser`.
* **`scripts/export_schemas.py --check` is not wired into CI or pre-commit.** The staleness test
  covers it inside the pytest run, so CI does catch drift; the `--check` mode is there for a faster
  pre-commit hook if the PM wants one. Belongs to `v1-e02-t06-import-boundary-guard` or a CI task.
* **`docs/session-reports/v1-e30-t01-caselist-data-use-policy.md` is missing its trailing newline**,
  so `pre-commit run --all-files` modifies it on every run. Left untouched here because it belongs to
  another task; a one-character fix for whoever next touches that file.
